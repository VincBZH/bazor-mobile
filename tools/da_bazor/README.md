# Da Bazor V0

Pilote local volontaire du [suivi #174](https://github.com/VincBZH/bazor-mobile/issues/174). Windows : extraire le dossier, double-cliquer `OUVRIR_DA_BAZOR.cmd`. Python 3 avec Tkinter requis. `python da_bazor.py status` produit un bilan lisible sans interface. `python da_bazor.py run` parcourt tous les projets, note les vérifications disponibles et les dépendances manquantes dans un checkpoint local, sans démarrer de service. Le lanceur ne crée aucun raccourci et aucune tâche de démarrage.

La fenêtre rouge s'ouvre au centre du bureau (lancement volontaire), avec onglets **Utilisables / à sonder**, **À réparer**, **En pause / écartés** et **Carte mentale**. Le bouton de la carte ouvre `ENCYCLOPEDIE_REPRISE_20260927.md`, complément daté de l'encyclopédie historique. Les décisions sur les projets liés au téléphone y sont déclassées conformément au choix de Vincent du 27 septembre : Bluetooth et éloignement provoquent trop de coupures.

Pour avoir un accès sur le Bureau Windows, double-cliquer une fois `CREER_LANCEUR_BUREAU.cmd` dans le dossier extrait. Il crée `DA BAZOR.cmd` sur le Bureau réel, y compris si le Bureau est redirigé, pointant vers le dossier extrait. Ne pas déplacer ni supprimer le dossier extrait ensuite. Si un lanceur du même nom existe déjà, il est conservé et la création s'arrête. Rien n'est ajouté au démarrage automatique.

La fenêtre sonde seulement `127.0.0.1` : Ollama 11434 (`/api/tags`), Core 8775 (`/api/v1/health`), Room 8765 (`/api/status`), Studio 8191 et ComfyUI 8188. Un bouton ouvre uniquement un port fixe ayant répondu ; une sonde ne certifie ni l'identité du processus ni un livrable. Elle demande une fois à Ollama un programme du jour en trois priorités. Le chat envoie exclusivement à Ollama local, d'abord `llama3.2:3b`, puis `qwen2.5-coder:7b` si le premier échoue et si le second est installé. Chaque essai a une limite de 45 secondes, 220 tokens de réponse ; pas d'appel externe payant. Le nom du modèle est contrôlé dans la réponse. Les rôles « chef » et « arbitre » désignent ici le contrôle de délai et le repli local, **pas** des agents IA supplémentaires.

Ce V0 **n'installe, ne modifie et ne livre encore aucun autre projet**. Les tâches Studio, Sabrina, Mission Locale, Windows Hello et démarrage Windows restent ouvertes avec leurs critères dans #174. Aucun PIN Windows n'est saisi dans l'outil ; aucune commande PowerShell, réponse de modèle ou instruction GitHub n'est exécutée. Pour que le clic sur l'icône Ollama ouvre cet accueil, il faudra identifier le raccourci réel sur le PC et créer un raccourci explicite vers ce lanceur ; ne pas remplacer le binaire Ollama.

## Étape 1 — démarrage Windows

Double-cliquer `AUDITER_DEMARRAGE_BAZOR.cmd` après extraction du dossier sur Windows. Il examine en lecture seule les clés Run/RunOnce, les dossiers Démarrage, les définitions de tâches planifiées et les services. Il crée `RAPPORT_DA_BAZOR_DEMARRAGE.txt` à côté du lanceur : transmettre seulement ce texte. Les commandes, chemins et détails restent dans un inventaire local privé sous `%LOCALAPPDATA%\BAZOR\DaBazor\startup_audit`. L'audit peut signaler une couverture partielle si Windows refuse un accès. Il ne désactive rien et ne peut pas prouver le résultat d'un redémarrage. Les raccourcis dont le nom ne révèle pas BAZOR, les mécanismes tiers et d'autres emplacements de lancement peuvent échapper à ce premier inventaire.

Après lecture du rapport, préparer une désactivation ciblée des entrées réellement présentes avec sauvegarde et restauration. Ne pas désactiver aveuglément Ollama, ComfyUI ou des services Windows. Le test de transaction sur copies fictives est aussi exécuté sur runner Windows dans la PR #172 ; cela ne vaut pas test du PC de Vincent.

### Désactivation ciblée après l'audit du 27 septembre

La version suivante inclut `DESACTIVER_DEMARRAGE_BAZOR.cmd` et `RESTAURER_DEMARRAGE_BAZOR.cmd`. La désactivation n'accepte **que les quatre empreintes** trouvées dans le rapport du PC de Vincent (deux tâches, deux raccourcis). Elle compare un nouvel inventaire au fichier privé de l'audit, copie les quatre entrées localement avant mutation, désactive les deux tâches via `schtasks.exe` et déplace les deux raccourcis vers la sauvegarde privée. En cas d'échec, elle tente de remettre les entrées déjà modifiées et marque `BLOCKED` si une restauration est incertaine. Le rapport `RAPPORT_DESACTIVATION_BAZOR.txt` ne contient pas de commandes ni de chemins.

Ne pas effacer `%LOCALAPPDATA%\BAZOR\DaBazor\startup_audit` : la sauvegarde y reste. Le lanceur de restauration réactive seulement les tâches et remet les raccourcis de la dernière transaction si leur identité n'a pas changé. Les clés Run et services restent inchangés. Une couverture `TASKS_PARTIEL` et l'absence de vérification après redémarrage empêchent de promettre un démarrage entièrement silencieux à ce stade.
